# LED光通信レシーバー

FPGA(Cyclone V E 開発キット)の拡張ボードのLEDが送る光の点滅を、スマホのカメラや動画から読み取り、文字に戻すWebページです。送信側のFPGA回路(VHDL)も `FPGA/` フォルダに入っています。

| 方式 | 送信回路 | 使うLED |
|---|---|---|
| 直列 | `optical_tx` | D1=クロック、D3=データ1ビット |
| 並列 | `optical_par2`(通常モード) | D1=クロック、D2〜D9=1バイト、D10=パリティ |
| カラー | `optical_par2`(PB3でカラーモード) | D2〜D9の赤=1バイト目、緑=2バイト目、D10=それぞれのパリティ |

どの方式も、D1(クロック)が1シンボルの真ん中で切り替わります。受信側はそのタイミングでデータを読むので、送信速度を前もって知らなくても受け取れます。同じフレーム `[同期] [文字数] [文字…] [チェックサム]` が繰り返し送られます。

## 使い方

- PCで使う:このフォルダごと保存し、`index.html` をChromeで開く(動画の読み込みとデモ信号が使える)
- スマホのカメラで使う:GitHub Pagesなど `https://` のページに置いて開く(カメラは https でしか使えない)
- 画面上で方式(並列 / カラー / 直列)を選び、LEDの位置を自動で探すか、D1 → D10 の順にタップして指定する
- LEDが白飛びするとき:Android の Chrome なら画面の「暗くする」で露出を下げる。iPhone などでは FPGA の PB3 を長押しして LED を暗くする
- 録画済みの動画が白飛びしているとき(カラーモード):「白飛びを除いて色を読む」をオンにし、「読み取る範囲」を広げて、LEDの周りのにじんだ光まで円に入るようにする(白く飛んだ中心には色が残っていないため、周りの光で赤か緑かを決める)
- 「映像の明るさ(表示だけ)」:画面に映す映像だけを暗くして、LEDや印を見やすくする。読み取りの計算には影響しない

## FPGA(送信側)

| ファイル | 内容 |
|---|---|
| `FPGA/tx/optical_tx.vhd` | 直列方式。5 / 10 / 15 / 20 bps |
| `FPGA/tx/pins.tcl` | `optical_tx` のピン割り当て |
| `FPGA/par/optical_par.vhd` | 並列方式・カラーモード。2 / 5 / 8 / 10 シンボル/秒。**中のエンティティ名は `optical_par2`** |
| `FPGA/par/pins_par.tcl` | `optical_par2` のピン割り当て |
| `FPGA/par/optical_par.sdc` | 50MHz クロックのタイミング制約 |

`optical_par2` のボタン:

| ボタン | 動作 |
|---|---|
| PB0 | 速度を切り替え(2 → 5 → 8 → 10 シンボル/秒) |
| PB1 | リセット(5シンボル/秒・メッセージ0・通常モード・明るさ100%) |
| PB2 | メッセージを切り替え(0〜3) |
| PB3 短押し | 通常モード ⇔ カラーモード |
| PB3 1秒長押し | LEDの明るさを切り替え(100% → 25% → 6% → 1.6%) |

メッセージは `optical_par.vhd` の `generic`(`MSG0`〜`MSG3`)で変えます。**受信ページは1〜64文字しか受け付けない**ので、64文字以内にしてください。

## ファイルの構成(Web側)

読み込む順番に並べています。`app.js` が最後に読み込まれ、そこで動き始めます。`import` を使わず、関数や変数をファイルをまたいで共有しているので、`index.html` の読み込み順を変えないでください(`file://` で開いても動くようにするため)。

| ファイル | 役割 |
|---|---|
| `index.html` | 画面の部品(ボタン・表示欄)と、ファイルがそろっているかの確認 |
| `style.css` | 見た目 |
| `js/tx-model.js` | 送信側のモデル(VHDLと同じ動き)。デモ信号とテストで使う |
| `js/channel.js` | 明るさ → 0/1 の判定 |
| `js/decode-serial.js` | 直列方式の復号 |
| `js/decode-parallel.js` | 並列方式の復号(旧方式と高精度受信) |
| `js/decode-color.js` | カラーモードの復号(赤と緑を別々に読み、2バイトずつ組み立てる) |
| `js/tracking.js` | 手ブレ補正 |
| `js/detect.js` | LEDの場所の自動検出 |
| `js/demux.js` | MP4 / MOV の読み取り |
| `js/view.js` | 映像の取り込み・描画・デモ信号 |
| `js/sources.js` | 動画ファイルとカメラ |
| `js/exposure.js` | カメラの露出の調整と、白飛びの割合の表示 |
| `js/diag.js` | 診断表示(LEDごとの判定・明暗の差・訂正回数)とログのCSV保存 |
| `js/app.js` | 操作と表示の更新 |

## 高精度受信のしくみ(decode-parallel.js)

1. クロック再生:クロックLEDの切り替わり時刻から周期と位相を推定し、見逃したシンボルも補う
2. 複数コマの平均:シンボルの中心付近のコマを、中心に近いほど重く平均して判定する
3. パリティ訂正:パリティが合わなければ、一番自信のない(境目に近い)ビットを反転する
4. 多数決:繰り返し届くフレームを、文字の位置ごとに多数決する

カラーモード(decode-color.js)は、この高精度受信を赤用と緑用に2つ動かし、同じ時刻に読んだシンボルを組にして2バイトずつ並べます。

## 変更するときの注意

- **送信側の仕様を変えるとき**:フレームの形・パリティ・ビットの並びは、VHDL・`js/tx-model.js`・各 `js/decode-*.js` の3か所で同じにする。直したらデモ信号で動作を確かめる
- **版を上げるとき**:版の文字列(今は `20261113-1200`)が、`index.html` の `?v=`・確認スクリプトの `V`・画面の版表示と、各JSファイル末尾の `window.LOADED` に書かれている。全部同じ値に置き換える(1か所でも違うと、画面に赤いエラーが出る)
